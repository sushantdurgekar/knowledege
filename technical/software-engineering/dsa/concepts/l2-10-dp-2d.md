# Dynamic programming: grids, knapsack, LCS and LIS

> Data Structures & Algorithms · L2 Proficient · Backtracking & dynamic programming · about 120 min · hub module `m10` ([open the hub](https://claude.ai/artifact/DQhszKFoe8qbiNbSpWkqM5))

## Why it matters
Most medium DP problems use two indexes: a grid position, two string prefixes, or “items considered × capacity left”. Learn the main shapes (grid paths, 0/1 knapsack, longest common subsequence and edit distance, plus the one-index longest increasing subsequence) and you can read most DP problems at a glance.

## Pre-question (answer before reading)
**Q:** How similar are “kitten” and “sitting”? What smaller questions about their prefixes would help you decide?

<details><summary>Answer</summary>

The same question for shorter prefixes: if you know the answer for every pair of prefixes (“kitte” vs “sittin”, and so on), the full answer follows from the last characters. Two strings give a 2D table indexed by the two prefix lengths.

## 🍎 Story time (kid version)
**The toy room and the treasure-map road trip: Routes on the treasure map**

On the treasure map, the streets form a grid, and the car may only drive right or down. How many routes reach the treasure in the bottom-right corner? Tara writes a number at every crossing: the top row and the left column each get 1, because there's only one straight way there. Every other crossing gets the number above it plus the number to its left, because the car must arrive from one of those two. When she reaches the treasure, its number counts every route, and she never traced a single route by hand.

| In the story | In code |
|---|---|
| A crossing on the street grid | A state: dp[r][c] |
| Arriving from above or from the left | The recurrence: dp[r][c] = dp[r − 1][c] + dp[r][c − 1] |
| The top row and left column are all 1s | The base cases |
| Filling crossings row by row | The fill order: each cell's inputs are already done |

**Where the story breaks:** Real streets let you turn back; this grid only counts routes that never go up or left. And DP tables can hold anything (the cheapest route, the longest match), not just counts.

## Key ideas (grown-up version)
- **A 2D state** usually means “the answer for the first i of one thing and the first j of another” or “the answer at grid cell (i, j)”. Fill the table in an order where every cell's inputs are ready.
- **Grid paths**: dp[r][c] = dp[r − 1][c] + dp[r][c − 1] to count routes, or cost[r][c] + min(above, left) for the cheapest. One row of memory is enough.
- **0/1 knapsack**: dp[i][w] = the best value using the first i items with capacity w = max(skip: dp[i − 1][w], take: dp[i − 1][w − weight] + value). With a 1D array, loop w **downwards** so each item is used at most once.
- **Unbounded knapsack and coin change II**: loop w **upwards**, because an item may be reused. When counting combinations, put the coins in the outer loop so each combination is counted once.
- **LCS** (longest common subsequence): if a[i − 1] == b[j − 1], dp[i][j] = dp[i − 1][j − 1] + 1; otherwise max(dp[i − 1][j], dp[i][j − 1]). O(n·m).
- **Edit distance**: the same table shape. Delete, insert and replace read dp[i − 1][j], dp[i][j − 1] and dp[i − 1][j − 1], each + 1; a match costs nothing.
- **LIS** (longest increasing subsequence): dp[i] = 1 + max(dp[j]) over j < i with nums[j] < nums[i] (just 1 if there's no such j) is O(n²). Keeping the smallest tail for each length and binary-searching it gives O(n log n).
- **Rebuild the answer** by walking back through the table from the final cell, following the choice that produced each value.

## Comparisons
**Four 2D DP shapes**

| Problem | State | Recurrence | Time |
|---|---|---|---|
| Unique grid paths | dp[r][c] = routes to (r, c) | dp[r − 1][c] + dp[r][c − 1] | O(rows × cols) |
| 0/1 knapsack | dp[i][w] = best value, first i items, capacity w | max(dp[i − 1][w], dp[i − 1][w − wt] + val) | O(n × capacity) |
| LCS | dp[i][j] = LCS of a[:i] and b[:j] | match: dp[i − 1][j − 1] + 1; else max(up, left) | O(n × m) |
| Edit distance | dp[i][j] = edits to turn a[:i] into b[:j] | match: the diagonal; else 1 + min(three neighbours) | O(n × m) |

```python
def unique_paths(rows, cols):
    dp = [1] * cols                         # the first row: one way to each cell
    for _ in range(1, rows):
        for c in range(1, cols):
            dp[c] += dp[c - 1]              # from above (old dp[c]) + from the left
    return dp[-1]

def min_path_sum(grid):
    rows, cols = len(grid), len(grid[0])
    dp = [float("inf")] * cols
    dp[0] = 0
    for r in range(rows):
        dp[0] += grid[r][0]                 # the first column: only from above
        for c in range(1, cols):
            dp[c] = grid[r][c] + min(dp[c], dp[c - 1])
    return dp[-1]
```

```javascript
}
```

### 0/1 knapsack: the full table, then one row looped downwards
```python
def knapsack_2d(weights, values, cap):
    n = len(weights)
    dp = [[0] * (cap + 1) for _ in range(n + 1)]   # dp[i][w]: first i items, capacity w
    for i in range(1, n + 1):
        wt, val = weights[i - 1], values[i - 1]
        for w in range(cap + 1):
            dp[i][w] = dp[i - 1][w]                 # skip item i
            if wt <= w:
                dp[i][w] = max(dp[i][w], dp[i - 1][w - wt] + val)   # or take it
    return dp[n][cap]

def knapsack_1d(weights, values, cap):
    dp = [0] * (cap + 1)
    for wt, val in zip(weights, values):
        for w in range(cap, wt - 1, -1):            # downwards: each item at most once
            dp[w] = max(dp[w], dp[w - wt] + val)
    return dp[cap]

w, v = [1, 3, 4, 5], [1, 4, 5, 7]
print(knapsack_2d(w, v, 7), knapsack_1d(w, v, 7))
```

Output:
```text
9 9
```

- line 9: Taking item i reads row i − 1, so the item can't be counted twice.
- line 15: Going downwards, dp[w − wt] still holds the value from before this item was considered.

```javascript
function knapsack2d(weights, values, cap) {
  const n = weights.length;
  const dp = Array.from({ length: n + 1 }, () => new Array(cap + 1).fill(0));   // dp[i][w]
  for (let i = 1; i <= n; i++) {
    const wt = weights[i - 1], val = values[i - 1];
    for (let w = 0; w <= cap; w++) {
      dp[i][w] = dp[i - 1][w];                       // skip item i
      if (wt <= w) dp[i][w] = Math.max(dp[i][w], dp[i - 1][w - wt] + val);   // or take it
    }
  }
  return dp[n][cap];
}

function knapsack1d(weights, values, cap) {
  const dp = new Array(cap + 1).fill(0);
  weights.forEach((wt, i) => {
    for (let w = cap; w >= wt; w--) dp[w] = Math.max(dp[w], dp[w - wt] + values[i]);   // downwards
  });
  return dp[cap];
}

const w = [1, 3, 4, 5], v = [1, 4, 5, 7];
```

### LCS (2D table) and LIS (tails + binary search)
```python
from bisect import bisect_left

def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1          # use the matching character
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])   # drop one character
    return dp[-1][-1]

def lis(nums):                                   # O(n log n)
    tails = []                                   # tails[k]: smallest tail of an increasing subsequence of length k + 1
    for x in nums:
        i = bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)                      # x extends the longest subsequence so far
        else:
            tails[i] = x                         # a smaller tail for length i + 1
    return len(tails)

print(lcs("abcde", "ace"), lcs("abc", "def"), lis([10, 9, 2, 5, 3, 7, 101, 18]), lis([7, 7, 7]))
```

Output:
```text
3 0 4 1
```

- line 7: dp[i][j] describes a[:i] and b[:j], so the characters to compare are a[i − 1] and b[j − 1].
- line 16: `bisect_left` keeps the subsequence strictly increasing: an equal number replaces a tail instead of extending.

```javascript
function lcs(a, b) {
  const dp = Array.from({ length: a.length + 1 }, () => new Array(b.length + 1).fill(0));
  for (let i = 1; i <= a.length; i++)
    for (let j = 1; j <= b.length; j++)
      dp[i][j] = a[i - 1] === b[j - 1]
        ? dp[i - 1][j - 1] + 1                   // use the matching character
        : Math.max(dp[i - 1][j], dp[i][j - 1]);  // drop one character
  return dp[a.length][b.length];
}

function lis(nums) {                             // O(n log n)
  const tails = [];                              // tails[k]: smallest tail of an increasing subsequence of length k + 1
  for (const x of nums) {
    let lo = 0, hi = tails.length;               // lower bound: the first tail >= x
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (tails[mid] < x) lo = mid + 1;
      else hi = mid;
    }
    tails[lo] = x;                               // extends (lo === length) or improves a tail
  }
  return tails.length;
}

console.log(lcs("abcde", "ace"), lcs("abc", "def"), lis([10, 9, 2, 5, 3, 7, 101, 18]), lis([7, 7, 7]));
```

Output:
```text
3 0 4 1
```

- line 5: dp[i][j] describes a[:i] and b[:j], so the characters to compare are a[i − 1] and b[j − 1].

## Worked example
**Problem.** Edit distance: the fewest single-character inserts, deletes or replacements that turn string a into string b (LeetCode 72).

1. State: dp[i][j] = the fewest edits to turn the first i characters of a into the first j characters of b.
2. Base cases: dp[i][0] = i (delete everything) and dp[0][j] = j (insert everything).
3. If a[i − 1] == b[j − 1], no edit is needed: dp[i][j] = dp[i − 1][j − 1]. Otherwise 1 + min(dp[i − 1][j] (delete), dp[i][j − 1] (insert), dp[i − 1][j − 1] (replace)).
4. Fill row by row: O(n · m) time and space (O(m) space with two rows).

```python
def edit_distance(a, b):
    n, m = len(a), len(b)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n + 1):
        dp[i][0] = i                        # delete all i characters
    for j in range(m + 1):
        dp[0][j] = j                        # insert all j characters
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]     # a match is free
            else:
                dp[i][j] = 1 + min(dp[i - 1][j],      # delete a[i - 1]
                                   dp[i][j - 1],      # insert b[j - 1]
                                   dp[i - 1][j - 1])  # replace
    return dp[n][m]

print(edit_distance("kitten", "sitting"), edit_distance("horse", "ros"),
      edit_distance("intention", "execution"), edit_distance("", "abc"))
```

Output:
```text
3 3 5 3
```

```javascript
function editDistance(a, b) {
  const n = a.length, m = b.length;
  const dp = Array.from({ length: n + 1 }, () => new Array(m + 1).fill(0));
  for (let i = 0; i <= n; i++) dp[i][0] = i;   // delete all i characters
  for (let j = 0; j <= m; j++) dp[0][j] = j;   // insert all j characters
  for (let i = 1; i <= n; i++)
    for (let j = 1; j <= m; j++)
      dp[i][j] = a[i - 1] === b[j - 1]
        ? dp[i - 1][j - 1]                      // a match is free
        : 1 + Math.min(dp[i - 1][j],            // delete a[i - 1]
                       dp[i][j - 1],            // insert b[j - 1]
                       dp[i - 1][j - 1]);       // replace
  return dp[n][m];
}

console.log(editDistance("kitten", "sitting"), editDistance("horse", "ros"),
            editDistance("intention", "execution"), editDistance("", "abc"));
```

Output:
```text
3 3 5 3
```

**Answer.** 3, 3, 5 and 3. kitten → sitting: replace k with s, replace e with i, insert g. Walking back through the table from dp[n][m] recovers exactly which edits were made.

## Traps & misconceptions
- **“The loop direction in a 1D knapsack doesn't matter.”** Looping capacity upwards lets an item be added again in the same pass (that's the unbounded knapsack). For 0/1 knapsack, loop capacity downwards.
- **“Coin change II: loop amounts on the outside and coins inside.”** That counts orderings (1 + 2 and 2 + 1 separately). Put the coins in the outer loop to count combinations.
- **“LCS and longest common substring share a recurrence.”** On a mismatch, LCS takes max(up, left). A substring must be contiguous, so it resets to 0, and the answer is the largest cell in the table.
- **“Off-by-one doesn't matter with a padded table.”** With an (n + 1) × (m + 1) table, dp[i][j] describes a[:i] and b[:j], so compare a[i − 1] with b[j − 1]. Mixing the two conventions is the most common 2D DP bug.
- **“The tails array in the fast LIS is the subsequence itself.”** Its length is right, but its contents can mix different subsequences. To rebuild the subsequence you need parent pointers.
- **“`[[0] * m] * n` makes a DP table.”** It makes n references to one row (the aliasing bug from L1), so every update leaks into every row. Build each row separately.

## Discussion prompts
- **Why does the tails trick make LIS O(n log n)?**
  <details><summary>One good answer</summary>tails stays sorted, so each new number finds its place by binary search in O(log n) and does O(1) other work. Swapping a tail for a smaller value keeps every option open for longer subsequences later.</details>
- **How do you find which items a knapsack solution took?**
  <details><summary>One good answer</summary>Keep the full 2D table and walk back from dp[n][cap]: if dp[i][w] differs from dp[i − 1][w], item i was taken, so subtract its weight; then move up to row i − 1.</details>

## Teach-back
**Prompt:** Explain to a junior colleague how the LCS table works for “abcde” and “ace”.

Rubric:
- [ ] dp[i][j] = the LCS length of the first i characters of a and the first j of b
- [ ] Row 0 and column 0 are 0 (an empty prefix)
- [ ] Match: the diagonal + 1; mismatch: the larger of up and left
- [ ] The answer is dp[n][m]; O(n·m) time
- [ ] Mentions rebuilding the subsequence by walking back, or shrinking the memory

<details><summary>Model answer</summary>

Make a table with a row for each prefix of “abcde” (including the empty prefix) and a column for each prefix of “ace”. dp[i][j] is the length of the longest common subsequence of those two prefixes, so the first row and column are 0. Fill it row by row: if the last characters of the two prefixes match, the best is one more than the cell diagonally up and to the left; if they don't, drop one of the two characters and take the better of the cell above and the cell to the left. The bottom-right cell holds the answer, 3 for “ace”. It's O(n·m) time and space, and walking back from that cell, taking the diagonal on matches, rebuilds the subsequence itself.

</details>

## Quick Q&A (also in the SRS deck)
- **Unique paths recurrence?** dp[r][c] = dp[r − 1][c] + dp[r][c − 1], with the first row and column all 1.
- **0/1 knapsack recurrence?** dp[i][w] = max(dp[i − 1][w], dp[i − 1][w − weight] + value).
- **Which way does a 1D 0/1 knapsack loop over capacity, and why?** Downwards, so each item counts at most once per pass.
- **LCS recurrence?** Match: dp[i − 1][j − 1] + 1. Otherwise max(dp[i − 1][j], dp[i][j − 1]).
- **Edit distance moves in the table?** Delete dp[i − 1][j], insert dp[i][j − 1], replace dp[i − 1][j − 1], each + 1; a match is free.
- **LIS in O(n log n)?** Keep tails[k], the smallest tail of an increasing subsequence of length k + 1, and binary-search each number's place.
