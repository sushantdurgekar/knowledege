# Dynamic programming: one dimension

> Data Structures & Algorithms · L2 Proficient · Backtracking & dynamic programming · about 110 min · hub module `m09` ([open the hub](https://claude.ai/artifact/DQhszKFoe8qbiNbSpWkqM5))

## Why it matters
Dynamic programming turns exponential brute force into short, fast loops whenever the same smaller question gets asked again and again. It's the most feared interview topic, and also the most formulaic once you learn to name the state.

## Pre-question (answer before reading)
**Q:** To count the ways to climb 5 stairs taking 1 or 2 steps at a time, what smaller questions do you need answered first?

<details><summary>Answer</summary>

The ways to reach stair 4 and stair 3: every route to stair 5 ends with a 1-step from 4 or a 2-step from 3. So ways(5) = ways(4) + ways(3), and those break down the same way.

</details>

## 🍎 Story time (kid version)
**The toy room and the treasure-map road trip: Sticky notes on the treehouse stairs**

Ben wants to know how many ways he can hop up the 10 stairs to the treehouse, taking one or two stairs at a time. He notices that every way to stair 10 comes from stair 9 or stair 8. So he works from the bottom up and sticks a note on each stair with its number of ways: stair 1 has 1 way, stair 2 has 2, stair 3 has 1 + 2 = 3, and so on. Each new note just adds the two notes below it. He never has to count the same stair twice.

| In the story | In code |
|---|---|
| “How many ways to reach stair 10?” | The state: dp[i] = the number of ways to reach step i |
| Every way to stair 10 comes from stair 9 or stair 8 | The recurrence: dp[i] = dp[i − 1] + dp[i − 2] |
| The notes on stairs 1 and 2, written first | Base cases: dp[1] = 1, dp[2] = 2 |
| Sticky notes, so no stair is counted twice | Memoisation or a table: each subproblem is solved once |

**Where the story breaks:** Ben's notes can hold any number, but JavaScript's numbers stop being exact after stair 77 (the count passes 2⁵³), so big counts need BigInt; Python's ints have no such limit. And real DP problems often need more than one number per stair, such as whether the last hop was a 2-step.

## Key ideas (grown-up version)
- **Use DP when** a problem has optimal substructure (the answer is built from answers to smaller versions) and overlapping subproblems (the same smaller versions come up again and again).
- **Four steps**: (1) define the state in words, such as “dp[i] = the best answer for the first i items”; (2) write the recurrence; (3) set the base cases; (4) choose the order (top-down memo or bottom-up table) and where the final answer sits.
- **Top-down (memoisation)**: write the recursion and cache the results (`@functools.cache` / a `Map`). Closest to the brute force; deep recursion can be a problem for large n.
- **Bottom-up (tabulation)**: fill a table from the base cases upwards in a loop. No recursion limit, and easy to shrink.
- **Space optimisation**: when dp[i] only reads the last one or two values, keep two variables instead of the whole array: O(1) space.
- **Classic 1D shapes**: count the ways (stairs, decode ways), minimum cost (coin change), take-or-skip (house robber: `dp[i] = max(dp[i − 1], dp[i − 2] + nums[i])`), best-ending-here (Kadane's maximum subarray), and yes/no splits (word break: can the first i characters be split?).
- **Mark impossible states**: coin change starts every amount above 0 at infinity (“can't make it yet”) and returns −1 if the target is still infinity at the end.
- **Complexity** = number of states × work per state: coin change is O(amount × coins); house robber is O(n).

## Diagrams
**Climbing stairs: dp[i] = dp[i − 1] + dp[i − 2]**

| dp | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| value | 1 | 1 | 2 | 3 | **5** | **8** | 13 |

_dp[0] = 1 (one way to stand still) and dp[1] = 1. Each cell adds the two before it: dp[6] = 5 + 8 = 13._

**House robber: rob a house, or skip it**

| value | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| value | 2 | 7 | 9 | 3 | 1 |

| best | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| value | 2 | 7 | 11 | 11 | 12 |

_best[i] = max(skip house i: best[i − 1], rob it: best[i − 2] + value[i]). The best total is 12 = 2 + 9 + 1._

## Comparisons
**Top-down or bottom-up?**

|  | Top-down (memoised recursion) | Bottom-up (table) |
|---|---|---|
| How you write it | The natural recursion plus a cache | A loop that fills dp in order |
| States computed | Only the ones actually needed | All of them |
| Recursion limit | Python stops near 1,000 deep; Node.js overflows after several thousand frames | None |
| Shrinking the memory | Hard | Easy: keep only what the recurrence reads |
| Good first draft? | Yes: closest to the brute force | Yes, once the fill order is clear |

## Code (JavaScript + Python)
### Climbing stairs: brute force, memoised, two variables
```python
from functools import cache

def climb_brute(n):                     # O(2^n): recomputes the same stairs
    if n <= 1:
        return 1
    return climb_brute(n - 1) + climb_brute(n - 2)

@cache
def climb_memo(n):                      # O(n): each stair solved once
    if n <= 1:
        return 1
    return climb_memo(n - 1) + climb_memo(n - 2)

def climb_table(n):                     # O(n) time, O(1) space
    prev2, prev1 = 1, 1                 # dp[0], dp[1]
    for _ in range(2, n + 1):
        prev2, prev1 = prev1, prev1 + prev2
    return prev1

print(climb_brute(20), climb_memo(20), climb_table(20), climb_table(70))
```

Output:
```text
10946 10946 10946 308061521170129
```

- line 6: Each call makes two more, so the number of calls grows exponentially (about 1.6× per extra stair): about 22,000 calls for n = 20.
- line 17: dp[i] only needs the previous two values, so two variables replace the whole table.

```javascript
function climbBrute(n) {                // O(2^n): recomputes the same stairs
  if (n <= 1) return 1;
  return climbBrute(n - 1) + climbBrute(n - 2);
}

const memo = new Map();
function climbMemo(n) {                 // O(n): each stair solved once
  if (n <= 1) return 1;
  if (!memo.has(n)) memo.set(n, climbMemo(n - 1) + climbMemo(n - 2));
  return memo.get(n);
}

function climbTable(n) {                // O(n) time, O(1) space
  let prev2 = 1, prev1 = 1;             // dp[0], dp[1]
  for (let i = 2; i <= n; i++) [prev2, prev1] = [prev1, prev1 + prev2];
  return prev1;
}

console.log(climbBrute(20), climbMemo(20), climbTable(20), climbTable(70));
```

Output:
```text
10946 10946 10946 308061521170129
```

- line 9: Check the cache first; compute and store only on a miss.
- line 15: dp[i] only needs the previous two values, so two variables replace the whole table.

### Take-or-skip (house robber) and best-ending-here (Kadane)
```python
def rob(nums):                          # dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])
    prev2, prev1 = 0, 0                 # best totals two houses back and one house back
    for x in nums:
        prev2, prev1 = prev1, max(prev1, prev2 + x)
    return prev1

def max_subarray(nums):                 # Kadane: the best sum of a run ending here
    best = cur = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)           # extend the run, or start fresh at x
        best = max(best, cur)
    return best

print(rob([2, 7, 9, 3, 1]), rob([1, 2, 3, 1]), rob([]), rob([5]))
print(max_subarray([-2, 1, -3, 4, -1, 2, 1, -5, 4]), max_subarray([-3, -1, -2]))
```

Output:
```text
12 4 0 5
6 -1
```

- line 4: Skip this house (keep prev1) or rob it (prev2 + x, because the neighbour must be skipped).
- line 10: A run ending at x either extends the best run ending at the previous element or starts over at x.

```javascript
function rob(nums) {                    // dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])
  let prev2 = 0, prev1 = 0;             // best totals two houses back and one house back
  for (const x of nums) [prev2, prev1] = [prev1, Math.max(prev1, prev2 + x)];
  return prev1;
}

function maxSubarray(nums) {            // Kadane: the best sum of a run ending here
  let best = nums[0], cur = nums[0];
  for (const x of nums.slice(1)) {
    cur = Math.max(x, cur + x);         // extend the run, or start fresh at x
    best = Math.max(best, cur);
  }
  return best;
}

console.log(rob([2, 7, 9, 3, 1]), rob([1, 2, 3, 1]), rob([]), rob([5]));
console.log(maxSubarray([-2, 1, -3, 4, -1, 2, 1, -5, 4]), maxSubarray([-3, -1, -2]));
```

Output:
```text
12 4 0 5
6 -1
```

- line 3: Skip this house (keep prev1) or rob it (prev2 + x, because the neighbour must be skipped).

## Worked example
**Problem.** Given coin values and an amount, what is the fewest number of coins that make the amount exactly? Return −1 if it can't be made (LeetCode 322, Coin Change).

1. State: dp[a] = the fewest coins that make amount a (infinity if it can't be made).
2. Recurrence: dp[a] = 1 + min(dp[a − c]) over coins c ≤ a, because the last coin used is some c.
3. Base case: dp[0] = 0. Fill a = 1, 2, …, amount in order, so dp[a − c] is always ready.
4. The answer is dp[amount], or −1 if it's still infinity. O(amount × number of coins) time, O(amount) space.

```python
def coin_change(coins, amount):
    INF = float("inf")
    dp = [0] + [INF] * amount               # dp[a]: fewest coins for amount a
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1        # use coin c last
    return dp[amount] if dp[amount] != INF else -1

print(coin_change([1, 2, 5], 11), coin_change([2], 3), coin_change([1], 0),
      coin_change([186, 419, 83, 408], 6249))
```

Output:
```text
3 -1 0 20
```

```javascript
function coinChange(coins, amount) {
  const dp = [0, ...new Array(amount).fill(Infinity)];   // dp[a]: fewest coins for amount a
  for (let a = 1; a <= amount; a++)
    for (const c of coins)
      if (c <= a && dp[a - c] + 1 < dp[a]) dp[a] = dp[a - c] + 1;   // use coin c last
  return dp[amount] === Infinity ? -1 : dp[amount];
}

console.log(coinChange([1, 2, 5], 11), coinChange([2], 3), coinChange([1], 0),
            coinChange([186, 419, 83, 408], 6249));
```

Output:
```text
3 -1 0 20
```

**Answer.** 3 (5 + 5 + 1), −1 (odd amounts can't be made from 2s), 0 (no coins for amount 0) and 20. The infinity marker is what lets “impossible” survive the min() without being mistaken for a real count.

- (put the steps in order)

## Traps & misconceptions
- **“DP is just recursion.”** It's recursion *plus* reuse: without a cache or a table, overlapping subproblems make it exponential. Name the state and make sure each one is computed once.
- **“The base case doesn't matter much.”** Most DP bugs are base cases: for coin change dp[0] is 0 coins; for stairs it's 1 way (stand still). Check the recurrence by hand on the two smallest inputs.
- **“Start a minimum-DP table at 0.”** Then every amount looks free. Start at infinity (or amount + 1) for “impossible” and turn it into −1 at the end.
- **“Kadane's algorithm resets the sum to 0 whenever it goes negative.”** Only if you record the best sum *before* resetting and start the best at −∞. Clamping first (`cur = max(0, cur + x)`) or starting the best at 0 reports 0 for all-negative input like [−3, −1, −2], whose answer is −1. The safe form is `cur = max(x, cur + x)`, starting from the first element.
- **“`@cache` works on a function that takes a list.”** Lists aren't hashable, so `functools.cache` raises TypeError. Cache on indexes or tuples and keep the list outside the cached function.
- **“Top-down is always fine in Python.”** The recursion goes as deep as the chain of states: 10,000 stairs passes the default limit of about 1,000. Switch to the bottom-up loop.

## Discussion prompts
- **How do you find the DP state for a new problem?**
  <details><summary>One good answer</summary>Ask what you'd need to know about a prefix (or a smaller amount) to finish the problem from there. Write it as a sentence: “dp[i] is the best X using the first i items”. If the next step needs more information (did I rob the last house?), add it to the state.</details>
- **When is a greedy choice enough, and when do you need DP?**
  <details><summary>One good answer</summary>Greedy works when a locally best choice can never hurt later, as with coins 1, 5, 10 and 25. With coins 1, 3 and 4 and amount 6, greedy picks 4 + 1 + 1 (3 coins) but DP finds 3 + 3 (2 coins).</details>

## Teach-back
**Prompt:** Explain to a junior colleague how you turn a slow recursive solution into a dynamic-programming one, using climbing stairs.

Rubric:
- [ ] Spot the overlapping subproblems: ways(n) recomputes ways(n − 2) many times
- [ ] Define the state: dp[i] = the ways to reach step i
- [ ] Recurrence dp[i] = dp[i − 1] + dp[i − 2], with base cases
- [ ] Memoise (top-down) or fill a table (bottom-up): O(n)
- [ ] Shrink the space to two variables

<details><summary>Model answer</summary>

Start from the brute-force recursion: the ways to reach step n are the ways to reach n − 1 plus the ways to reach n − 2. It's exponential because ways(n − 2) is computed again inside ways(n − 1), and so on all the way down. The fix is to solve each subproblem once. Name the state, dp[i] = the number of ways to reach step i, keep the recurrence dp[i] = dp[i − 1] + dp[i − 2], and set the base cases dp[0] = dp[1] = 1. Then either cache the recursive function (top-down) or fill the table from the bottom up in a loop; both are O(n). Because each step only reads the previous two values, two variables are enough: O(1) space.

</details>

## Quick Q&A (also in the SRS deck)
- **Two signs that a problem needs DP?** Optimal substructure and overlapping subproblems.
- **The four steps of a DP solution?** Define the state, write the recurrence, set the base cases, choose the order (and where the answer is).
- **House robber recurrence?** dp[i] = max(dp[i − 1], dp[i − 2] + nums[i]).
- **Coin change: how do you mark amounts that can't be made?** Start them at infinity; if dp[amount] is still infinity at the end, return −1.
- **Kadane's update?** cur = max(x, cur + x); best = max(best, cur).
